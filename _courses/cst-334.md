Four programming assignments in C, building up from manual memory management to a working allocator. Close to a thousand lines of systems code across the set.

**Dynamic string library.** A growable string type over a raw `char*` buffer, with explicit capacity management and bounds-checked access. Reserve, resize, append, push and pop, plus the failure cases that matter: `at()` past the end, `back()` on an empty string, growth that has to preserve the null terminator without counting it against length.

**Process scheduler.** A simulator running the same workload through FIFO, Round Robin, Shortest Job First, and Priority scheduling. Each policy is a selector built on a comparator, so the scheduling decision is the only thing that changes and the simulation loop is shared. It reports average response and turnaround time, which is what actually exposes the tradeoff: Round Robin wins on response and loses on turnaround, SJF is the reverse.

**Memory management unit.** Two virtual memory schemes behind one interface. Base and bounds does first fit placement into contiguous physical regions. Paging extracts the virtual page number, decodes read, write, and execute permission bits out of a packed page table entry, and resolves to a frame. Multi-process isolation falls out of it: two address spaces holding the same VPN must never land on the same PFN. Available publicly as [mmu-simulator](https://github.com/ryebriscoe/mmu-simulator).

**Memory allocator.** A `malloc` and `free` replacement over a fixed arena and a free list. `mem_alloc` finds a chunk and splits it, `mem_free` walks back to the header and coalesces neighbors. First fit, best fit, and worst fit are switchable at runtime, and the free list can be kept in address order or size order, so the same workload produces measurably different fragmentation depending on the configuration.

The bit packing in the MMU was the hardest part. Permissions and the frame number share a word, and a wrong shift gives you a translation that looks plausible and is silently wrong, which is not something a test failure points at directly.
